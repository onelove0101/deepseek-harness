# Agent Note: Experts

Status: implemented

[English](2026-10-31-experts.md) | 中文

## 问题

用户若想在多个会话里使用同一套常驻角色、skill 和参考材料，只能重复输入，或手工组合 preset。preset 改变的是会话的整个 agent，skill 按名称调用，没有持久的角色，也没有私有的参考文本。系统里没有一个每用户一份、可由单条提示调用的对象，Host 上也没有保存用户文档的地方。

## 决策

**Expert（专家）** 包含小写的提及名、启用标志、Soul（常驻指令）、所选 skill 名称、所选文档和所选知识库。Host 包 `@deepseek-ai/dsh-expert`（`packages/preset/expert`）拥有 `experts` Remote 命名空间、持久化与调用。Client 包 `@deepseek-ai/dsh-client-ui-expert`（`packages/client/ui-expert`）拥有设置页与 `@` 菜单来源。

**存储。** `experts` 存储域有三张表：`experts`、`documents` 和 `knowledge_bases`。写入经由一个串行队列，每个 Remote 变更都返回整个文档库。文档只能是粘贴的文本。Host 不接受文件系统路径，也不接受 URL，文档文本从不返回给 Client；设置页只看到标题和字节长度。所有数量与大小都是必填的正整数 Config 字段：Expert 数、Soul 字节数、每个 Expert 的 skill 数、文档数、每个文档的字节数、知识库数、每个知识库的文档数、文档库字节数，以及每次调用注入的字节数。

**调用。** `agent/pre-step` 监听器先调用 `next()`，并忽略被拒绝的步骤。它只读取 Host 从浏览器用户处接纳的提示（消息来源为带 `rpcId` 的 `user`）中第一个文本块开头的提及，因此模型或子 agent 写出的消息不能调用 Expert。每一步调用一个 Expert，取自第一个开头提及，即使多条排队提示都提到了 Expert。监听器解析 Expert，从 skill 注册表加载每个所选 skill 的正文，并让 Soul、skill 和文档库文本合计落在同一个字节上限内，该上限按完整渲染后的消息（含包装和 XML 转义）计量。它向该步骤的决定追加一条 `user/message`。文本经过 XML 转义，文档库被标记为不受信任的参考材料。

**回放。** 调用消息是普通的已记录 `user/message`，因此模型从 Expert 看到的一切都在注入时写入了 Session 日志。之后编辑或删除 Expert 或文档不会改变回放的历史。该消息使用现有来源 `{ kind: 'plugin', plugin: 'expert', form: 'instructions' }`，所以 `SESSION_FORMAT_VERSION` 保持 3，持久化门禁也没有列出任何变更。

**设置页。** 页面注册 `settings.section` id `experts`，顺序 23，位于 Skills（22）与已归档会话（25）之间。页面打开时一并读取文档库与 skill 清单。切换启用开关通过与表单相同的 Remote 保存 Expert。

**`@` 菜单。** 页面为 `@` 注册一个 input-trigger 来源，只在开头位置提供已启用的 Expert，选择后插入字面文本 `@name `。提示发送时由 Host 执行注入。

## 考虑过的替代方案

**新的消息来源类型。** 专用的 `expert` 来源能让 UI 更精确地标注该消息，但联合类型的任何新成员都会改变持久化词汇，需要升级 Session 格式并提供迁移。通用的 `plugin` 来源承载的信息相同。

**行内提及。** 在提示任意位置解析 `@name` 会允许单条提示出现多个 Expert，并与邮件地址、文件引用等普通 `@` 文本冲突。开头位置与 `/` skill 菜单一致，也让每条提示一个 Expert 不产生歧义。

**按路径或 URL 上传文档。** Host 中没有能在限制下保存用户文本的上传机制。接受路径或 URL 意味着代浏览器读取文件和网络，所以文档库改为接受粘贴的文本。

**把文档文本返回给设置页。** 页面只需要标题和大小；不返回文本可避免每次读取文档库都携带大量载荷。

**把加号菜单做成独立的 Expert 选择器。** 加号菜单就是 `/` 命令来源的“添加”分组，所以 Expert 行是一个命令贡献，其 `flyout` 列出 Host 排序后的 Expert（`experts.ranked`，使用最多的在前）。选择后插入与 `@` 菜单相同的开头 `@name ` 文本，并且不会发送。该 flyout 是 `ui-input-trigger` 与 `ui-commands` 中通用的 `submenu` 机制；菜单没有左右键，所以用 Enter、Tab 和点击打开它。

## 影响

只有开头的提及会调用 Expert；加号菜单会插入该提及。文档只能是文本。skill 名称在调用时校验，所以选择之后被移除的 skill 会在消息内被标注为不可用，Expert 的其余部分仍然生效。依赖工作区目录的项目 skill 不会出现在选择器中。调用消息在该轮之后仍留在 Session 中，所以之后的请求会持续消耗其 token，直到压缩移除它；该消息追加在已有历史之后，因此更早的提示缓存前缀仍然有效。`@` 菜单和加号菜单 flyout 每次打开都会调用 `experts.ranked`，并且在 `@` 后输入时按查询过滤而保留 Host 的使用排序。设置页缓存的其他客户端文档库元数据会在重连或页面重新加载后出现。
