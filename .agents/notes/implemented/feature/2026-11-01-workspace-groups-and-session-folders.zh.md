# Agent Note: Workspace Groups and Session Folders

Status: implemented

[English](2026-11-01-workspace-groups-and-session-folders.md) | 中文

## Problem

工作区注册表已经持久保存组，但控制器的重连基线只列出顶层工作区，浏览器也没有持久组布局。因此，移入组的工作区会在流重连或重新加载后从浏览器中消失。

侧边栏在工作区下也没有持久展示结构。用户无法通过明确的浏览器操作组织相关工作区，也无法在不改变工作目录或持久化的情况下归档工作区所属的会话。

## Decision

`ctx.workspaceRegistry` 提供持久工作区组和工作区本地的逻辑会话文件夹。组拥有有序工作区 id。注册表的 `workspaceIds` 保存顶层工作区顺序，每个工作区位于该顺序中或恰好位于一个组中。移动工作区只改变此布局；解散组会将其工作区返回顶层，不改变目录、文件、会话或会话历史。

工作区记录内嵌有序文件夹记录。文件夹只包含其所属工作区已登记的会话 id；一个会话至多出现在一个文件夹中。未出现在任何文件夹的会话保留在工作区根目录。归档不会改变工作区归属、会话 cwd、会话日志或文件系统状态。删除文件夹会将其会话返回工作区根目录，而不会删除会话数据。

控制器发布权威布局，其中包括每个工作区、顶层工作区顺序、有序组以及文件夹成员资格。结构性组和根布局变更替换该布局；仅文件夹变更会更新受影响的工作区。浏览器以组 → 工作区 → 文件夹的层级使用此布局，并为组和文件夹操作提供本地化、可通过键盘访问的菜单和对话框。既有拖拽排序保留其原有本地或根目录行为，不会变成持久的跨组或跨文件夹移动。

## Durability and recovery

组转移继续使用注册表待定变更记录，因为其状态跨越全局注册表记录和组记录。重启恢复会完成已命名的中断转移。文件夹变更更新单条工作区记录，普通工作区记录写入会保持排他且已归属的文件夹成员资格。缺少 `folders` 字段的旧版第二版工作区记录会读取为空文件夹列表；存储领域版本仍为二，因为记录默认值无法迁移独立版本化的存储介质。

## Alternatives considered

**保留现有扁平控制器基线。** 不采用，因为 `list()` 有意只返回顶层工作区，这会使分组工作区不可见，客户端也无法在重连后重建组成员资格。

**将文件夹表示为文件系统目录。** 不采用，因为归档是展示组织，不是源代码树管理。创建、移动或删除目录会改变会话执行上下文，并引入工作区记录并不拥有的破坏性文件系统语义。

**让拖放持久保存组或文件夹移动。** 不采用，因为既有拖拽行为具有更窄的排序语义。明确的菜单操作让布局变更可发现且可访问，同时不会悄然改变既有拖拽行为。

**为文件夹提升工作区存储领域版本。** 不采用，因为存储层会在记录解析前验证领域版本。保持第二版并使用空数组记录默认值可以安全读取现有原始记录，而不宣称进行了介质迁移。

## Verification

工作区测试覆盖文件夹创建、重命名、归档、返回根目录、排他成员资格、删除、无效所有权和文件夹引用、时间戳、永久会话删除清理、损坏拒绝以及旧版第二版原始记录。控制器和客户端测试覆盖权威组布局、重连状态、组和文件夹命令以及流与一元调用的收敛。组件测试覆盖本地化组和文件夹操作、确认流程和层级渲染。基于 `SlotTestRuntime` 的真实组合测试覆盖通过组装浏览器的组创建：视图选项对话框触发注入的 `createGroup` 控制器调用，组行从权威布局渲染。

## Consequences

组或文件夹是持久用户组织，但两者都不是文件系统对象。该层级获得状态和明确操作，代价是保持物理目录布局、会话执行上下文和先前拖拽语义不变。分组工作区现在会在浏览器重新加载和重连后保持可见。
