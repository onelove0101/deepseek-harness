# Agent Note: Experts

Status: implemented

English | [中文](2026-10-31-experts.zh.md)

## Problem

A user who wants the same standing role, skills, and reference material in many sessions had to retype it or hand-compose a preset. Presets change the whole agent for a session, and skills are invoked by name without a durable role or private reference text. There was no per-user object that a single prompt could invoke, and no Host-side place to keep user documents for it.

## Decision

An **Expert** has a lowercase mention handle, an enabled flag, a Soul (standing instructions), selected skill names, selected documents, and selected knowledge bases. The Host package `@deepseek-ai/dsh-expert` (`packages/preset/expert`) owns the `experts` Remote namespace, persistence, and invocation. The Client package `@deepseek-ai/dsh-client-ui-expert` (`packages/client/ui-expert`) owns the Settings page and the `@` menu source.

**Storage.** The `experts` storage domain has three tables: `experts`, `documents`, and `knowledge_bases`. Writes go through one serialized queue and every Remote mutation returns the whole library. Documents are pasted text only. The Host accepts no filesystem path and no URL, and document text is never returned to Clients; the Settings page sees title and byte length. Every count and size is a required positive-integer Config field: Experts, Soul bytes, skills per Expert, documents, bytes per document, knowledge bases, documents per knowledge base, library bytes, and bytes injected per invocation.

**Invocation.** An `agent/pre-step` listener calls `next()` first and ignores rejected steps. It reads a mention only at the start of the first text block of a prompt the Host admitted from a browser user (message source `user` with an `rpcId`), so model-written or subagent-written messages cannot invoke an Expert. One Expert is invoked per step, taken from the first leading mention, even when several queued prompts mention Experts. The listener resolves the Expert, loads each selected skill body from the skill registry, and fits the Soul, skills, and library text under one byte bound measured on the complete rendered message, including wrappers and XML escaping. It appends one `user/message` to the step decision. The text is XML-escaped and the library is framed as untrusted reference material.

**Replay.** The invocation message is an ordinary logged `user/message`, so everything the model sees from an Expert is in the Session log at injection time. Editing or deleting an Expert or document afterward does not change replayed history. The message uses the existing source `{ kind: 'plugin', plugin: 'expert', form: 'instructions' }`, so `SESSION_FORMAT_VERSION` stays 3 and the persistence gate lists no change.

**Settings page.** The page registers `settings.section` id `experts` at order 23, between Skills (22) and Archived sessions (25). It reads the library and the skill inventory together when it opens. Toggling the enabled switch saves the Expert through the same Remote as the form.

**`@` menu.** The page registers an input-trigger source for `@` that offers enabled Experts at the leading position only, and a pick inserts the literal `@name `. The Host performs the injection when the prompt is sent.

## Alternatives considered

**A new message source kind.** A dedicated `expert` source would label the message precisely in UIs, but any new member of the source union changes the persisted vocabulary and needs a Session format bump with migration. The generic `plugin` source carries the same information.

**Inline mentions.** Resolving `@name` anywhere in the prompt would allow several Experts per prompt and conflict with ordinary `@` text such as email addresses and file references. The leading position matches the `/` skill menu and keeps one Expert per prompt unambiguous.

**Document upload by path or URL.** No upload seam exists in the Host that stores user-owned text under bounds. Accepting a path or URL would add file and network reads on behalf of a browser, so the library takes pasted text instead.

**Returning document text to the Settings page.** The page needs titles and sizes only; withholding the text keeps the large payload off every library read.

**Plus-menu selection as a separate Expert picker.** The plus menu is the `/` command source's Add section, so the Expert row is a command contribution whose `flyout` lists the Host-ranked Experts (`experts.ranked`, most used first). A pick inserts the same leading `@name ` text as the `@` menu and never sends. The flyout is a generic `submenu` seam in `ui-input-trigger` and `ui-commands`; Enter, Tab, and click open it because the menu has no left and right keys.

## Consequences

Only the leading mention invokes an Expert; the plus menu inserts that mention. Documents are text only. Skill names are validated at invocation, so a skill removed after selection is reported inside the message as unavailable and the rest of the Expert still applies. Project skills that need a workspace directory are not offered in the picker. The invocation message stays in the Session after the turn, so later requests keep paying its tokens until compaction removes it; the message is appended after existing history, so earlier prompt-cache prefixes stay valid. The `@` menu and plus-menu flyout call `experts.ranked` on every open, and typed `@` filtering preserves the Host's usage order. The Settings page's cached library metadata from another client appears after a reconnect or page reload.

## Testing

`packages/preset/expert/tests/expert.spec.ts` covers the Remote methods, bounds at exact and oversized limits in UTF-8 bytes, referential cleanup on deletion, refusal of invalid names and duplicate handles, persistence across restart, and the invocation path: one injected message, plain prose for unknown, disabled, or non-leading mentions, no injection on rejected steps, a snapshot that later edits do not alter, and omission of documents over the invocation budget. `packages/preset/expert/tests/invocation.spec.ts` covers leading-mention parsing, library selection under the byte budget, and message rendering with escaping. The client tests under `packages/client/ui-expert/tests` cover the controller, components, the plugin registration, the `@` source, and disposal. `packages/client/ui-settings-general/tests/shell.client.spec.ts` and `apps/web/tests/expected/settings-chrome/dialog-en.expected.md` pin the navigation entry.
